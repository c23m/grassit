# Grassit 产品需求文档

## 一、目标

为个人博客 + Wiki 提供一个自托管的内容系统，支持文章发布、用户认证、文件存储。

## 二、不做什么

- 不做多租户（只有单一站点，不服务多个独立博客）
- 不做富文本编辑器（用 Markdown）

## 三、用户系统

### 3.1 注册

**必填：**

- 用户名 `username`
- 昵称 `nickname`（≤30 字符）
- 密码 `password`（6~128 字符）

**可选：**

- 邮箱 `email`

### 3.2 用户字段

| 字段             | 约束                                                                   | 可变      |
| ---------------- | ---------------------------------------------------------------------- | --------- |
| `username`       | 唯一、必需，≤30 字符，只允许 `a-z A-Z 0-9 - _`，不能以 `-` 或 `_` 开头 | ❌ 不可变 |
| `nickname`       | 必需，≤30 字符，不唯一                                                 | ✅ 可变   |
| `created_at`     | 精确到日                                                               | ❌        |
| `avatar`         | URL，可空                                                              | ✅ 可变   |
| `email`          | 可空，非空时与账号一对一                                               | ✅ 可变   |
| `github`         | 可空，非空时与账号一对一                                               | ✅ 可变   |
| `role`           | `user` / `admin`，默认 `user`                                          | 见 3.4    |
| `banned_until`   | 解禁时间，允许 `NULL`（`NULL` 表示未被封禁）                           | 见 3.4    |
| `deleted`        | 是否已注销（软删除标记）                                               | 见 3.4    |

### 3.3 公开信息

以下字段对外可见：

- 用户名
- 昵称
- 创建时间
- 封禁状态（是否处于封禁中）

### 3.4 账号状态规则

角色和状态由三个字段决定，不再单独存一个"状态"：

| 字段           | 取值                | 说明                                      |
| -------------- | ------------------- | ----------------------------------------- |
| `role`         | `user` / `admin`    | 角色权限；管理员可以封禁 / 解封用户        |
| `banned_until` | 时间戳，允许 `NULL` | 解禁时间；`NULL` 表示没有被封禁            |
| `deleted`      | 布尔                | 是否已注销（软删除标记）                  |

推导出来的状态与对外表现：

| 状态   | 条件                              | 可被搜索 | 可见 | 备注                               |
| ------ | --------------------------------- | -------- | ---- | ---------------------------------- |
| 正常   | `banned_until` 为空或已过期        | ✅       | ✅   |                                    |
| 封禁中 | `banned_until` 还没到              | ✅       | ✅   | 显示封禁状态与解禁时间             |
| 已注销 | `deleted = true`                   | ❌       | ❌   | 文章仍存在，作者名显示"已注销用户"  |

`deleted = true` 优先于封禁：同一条记录两者都命中时，一律按已注销处理。

**封禁：**

- 个人信息可以查看，但不能登录，登录时提示账号异常
- 封禁时写 `banned_until`；到期即自动解封——判断时拿当前时间和它比较，不需要定时任务
- 管理员可以随时手动解封：把 `banned_until` 置回 `NULL`

**注销后：**

- 软删除：`deleted` 置为 `true`，数据库里保留这条记录，不做物理删除
- 邮箱、GitHub 等绑定在注销时自动解绑，解绑后可以被新账号使用（没有机制去拦，也不打算拦）
- 用户名不可被新用户注册（记录还在，唯一约束自然挡住）
- 已发布的文章仍可正常访问

`deleted = true` 或处于封禁中的账号都不能登录，登录时统一提示账号异常。

### 3.5 登录后可修改

- 昵称：可改，不可删
- 邮箱：可改、可解绑（解绑后为空，非空时一对一）
- GitHub：可绑定、可解绑（同邮箱规则）
- 密码：只能更新，不能解绑——用户名 + 密码这条路径始终保留（见 4.1）

## 四、认证

### 4.1 密码登录

- 提供 `username` + `password`
- 成功返回 access token
- 只要账号状态正常，用户名 + 密码始终可用：不依赖邮箱或 GitHub 是否绑定，第三方绑定只是多一种登录方式

### 4.2 GitHub 登录

- 前置条件：用户已绑定 GitHub
- 流程：OAuth 授权 → 回调 → 签发 token

### 4.3 邮箱登录

- 用户提供邮箱
- 系统查询绑定的账号
- 存在时发送 6 位数字验证码，有效期10分钟
- 有效期内，用户输入验证码登录

### 4.4 Token 策略

| Token         | 有效期  | 存放              |
| ------------- | ------- | ----------------- |
| access token  | 15 分钟 | 前端 localStorage |
| refresh token | 30 天   | HttpOnly Cookie   |

**请求头：** `Authorization: Bearer <token>`

**撤销：** 登出与封禁时把该用户当前的 access / refresh token 拉黑，名单存 Redis，按 token 剩余有效期设 TTL。JWT 本身无状态、撤不掉，只靠客户端清 token 不够。

## 五、文章系统

### 5.1 字段

| 字段         | 约束                                        |
| ------------ | ------------------------------------------- |
| `uuid`       | 唯一，不可变                                |
| `slug`       | 唯一，≤128 字符，只含小写字母和连字符，可变 |
| `title`      | 必需                                        |
| `content`    | 正文                                        |
| `author`     | 关联用户。若用户已注销，显示“已注销用户”    |
| `created_at` | 精确到分                                    |
| `updated_at` | 精确到分                                    |
| `tags`       | 标签集合，可按标签查询                      |
| `word_count` | UTF-8 字符数                                |
| `visibility` | 公开 / 私密，默认公开                       |

### 5.2 可见性规则

| 可见性 | 谁能访问             |
| ------ | -------------------- |
| 公开   | 任何人               |
| 私密   | 仅作者可访问或搜索到 |

### 5.3 删除规则

- **物理删除**，不是软删
- slug 释放，可被其他文章使用
- 删除后通过 uuid 或 slug 均不可访问

## 六、存储

### 6.1 路径约定

存储根目录由后端环境变量 `PUBLIC_DIR` 指定，并以 `/public` 前缀对外提供静态资源（见 `backend/app/main.py`）。

| 环境 | 根路径                       |
| ---- | ---------------------------- |
| 开发 | `./public`（后端工作目录下） |
| 生产 | `/var/lib/grassit/public`    |

### 6.2 目录结构

```
public/
├── static/
├── avatars/
└── attachments/
```

### 6.3 文件命名

对 `slug + 原始文件名` 取 SHA-256，取前 12 位作为存储文件名。

## 七、接口

### 7.1 BaseURL

前端所有请求统一走 `/api` 前缀（同域路径，不使用独立 API 子域）。

| 环境 | 前端请求   | 实际去向                                                                                             |
| ---- | ---------- | ---------------------------------------------------------------------------------------------------- |
| 开发 | `/api/...` | Vite dev server 代理到 `http://localhost:8000`，**剥掉 `/api` 前缀**（见 `frontend/vite.config.js`） |
| 生产 | `/api/...` | Nginx 反代到 `http://127.0.0.1:8000`，同样剥掉 `/api` 前缀                                           |

**路径规则：** 允许尾后斜杠；FastAPI 默认把 `/test/` 以 307 重定向到 `/test`。

### 7.2 接口

路径以实现（`backend/app/routers/`）为准；完整契约由后端导出 `openapi.json`。

| 接口                            | 说明                                                                       |
| ------------------------------- | -------------------------------------------------------------------------- |
| `POST /auth/register`           | 注册                                                                       |
| `POST /auth/login`              | 密码登录，返回 access token 与当前用户信息                                 |
| `POST /auth/logout`             | 登出，清除 refresh cookie                                                  |
| `POST /auth/refresh`            | 用 refresh token 换新的 access token                                       |
| `GET /users/me`                 | 当前登录用户                                                               |
| `GET /users/{username}`         | 用户公开信息                                                               |
| `DELETE /users/{username}`      | 管理员删除用户                                                             |
| `GET /articles`                 | 文章列表，支持 `author` / `title` / `slug` / `start` / `end` / `tags` 筛选 |
| `GET /articles/{identifier}`    | 文章详情（`identifier` 为 uuid 或 slug）                                   |
| `POST /articles`                | 创建文章                                                                   |
| `DELETE /articles/{identifier}` | 删除文章（仅作者）                                                         |

### 7.3 协议

- 生产环境使用 HTTPS
- 认证头：`Authorization: Bearer <token>`

### 7.4 错误码

| 状态码 | 含义         | 使用场景                                                 |
| ------ | ------------ | -------------------------------------------------------- |
| 400    | 请求不合法   | 业务规则不满足，但请求格式本身没问题（预留）             |
| 401    | 未认证       | 缺少或无效的 token；登录时用户名或密码错误               |
| 403    | 无权限       | 已登录但无权操作，如删除他人的文章                       |
| 404    | 不存在       | 目标用户或文章不存在                                     |
| 409    | 冲突         | 唯一约束冲突：用户名或邮箱已被占用                       |
| 422    | 参数校验失败 | 请求体或查询参数不符合 schema，由 FastAPI 校验层自动返回 |

唯一冲突的 `detail` 需要区分是用户名还是邮箱，便于前端定位到具体输入框。

## 八、待定

不紧急的功能、待补的技术、还没想清楚的问题都记在这里。版本安排见 [todo.md](todo.md)：本文件只写需求与已定的决策，不写排期。

### 8.1 不紧急的功能与技术

- **私信**：用户之间一对一发消息。属于"想做就做"的功能，不紧急；细节还没定（谁能给谁发、要不要屏蔽、要不要已读）
- **在线状态**（`is_online` / `last_online_at`）：在线 = 还保持着与服务器的连接，离线 = 连接断了；顺带记下断开时间
- **实时通信的承载方式还没定**（WebSocket / SSE）：已知要它做两件事——私信的消息实时送达、在线状态的连接在不在；用 WebSocket 还是 SSE、要不要顺带做站内通知，都没想清楚
- **P2P 联机（WebRTC）**：DataChannel 做点对点通信；信令通道能不能复用上面那条连接，还没定
- 单文件上传大小上限
- **AI 能力**：做不做、做到哪一步（文章摘要 / 基于自己文章库的问答 / 能调用后台工具的 Agent / 带记忆的对话），以及选型——自建模型还是云 API、向量库怎么选、成本上限
- Redis 除了登出与封禁的 token 黑名单，还要不要用于缓存与限流
- **桌面端 Electron**：把现有的 Vue 前端直接装进桌面壳，用 IPC 与系统能力（窗口、菜单、文件系统）打交道，最后打包成 Windows 应用——Web 那套不用重写
- **工程化**：日志与错误处理、接口契约导出（`openapi.json`）、CI

### 8.2 待补的知识

项目里已经用过、但只到"能看懂、照着写"的程度：

- JavaScript：数组高阶方法、解构与展开、作用域与闭包
- 异步：Promise、`async` / `await`——不只是会写 `await`，红线见 [AGENTS.md](../AGENTS.md)
- 浏览器：Web Storage（现在用 `@vueuse/core` 的封装）、Network 面板、curl
- HTTP：Headers、Cookie、Authorization
- 数据库：事务、数据库设计实践、SQLAlchemy 表关系

`this`、原型链、class 与继承这些没列：组件全是 `<script setup>`，不碰 `this`，那几样只在读 Vue 2 / Options API 的旧代码时才用得上，需要了再补。

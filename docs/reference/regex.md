# 正则校验速查

> 参考笔记（学习用），不是项目规范。示例代码由 AI 生成、未经审阅，以实测与官方文档为准。
> 实测环境：Pydantic 2.13.5（pattern 由 Rust regex 引擎执行），文中行为均已实际跑通。

## Pydantic 的 pattern 是"子串匹配"

```python
class M(BaseModel):
    name: str = Field(pattern=r"[a-z]+")
```

| 输入       | 结果                          |
| ---------- | ----------------------------- |
| `"abc"`    | 通过                          |
| `"abc123"` | **通过**（子串 `abc` 命中了） |
| `"123ABC"` | 拒绝                          |

语义相当于 `re.search`：**只要字符串里有一处匹配就通过**。所以要做整串校验，必须自己写锚点：

```python
username: str = Field(
    min_length=3,
    max_length=30,
    pattern=r"^[a-zA-Z0-9][a-zA-Z0-9_-]*$",
)
```

## Python 标准库 re 的三个入口

| 函数           | 语义                     | `[a-z]+` 对 `"abc123"` |
| -------------- | ------------------------ | ---------------------- |
| `re.match`     | 从串首开始，前缀命中即可 | 通过                   |
| `re.search`    | 任意位置命中即可         | 通过                   |
| `re.fullmatch` | 必须整串匹配             | 拒绝                   |

## `$` 与 `\Z` 的差别

默认 `^` / `$` 匹配串首与串尾；开了 `re.MULTILINE` 之后 `$` 变成"行尾"。对 `"abc\ndef"` 实测：

| 写法                                       | 结果                |
| ------------------------------------------ | ------------------- |
| `re.search(r"^[a-z]+$", s)`                | 不匹配              |
| `re.search(r"^[a-z]+$", s, re.MULTILINE)`  | 匹配（只看首行）    |
| `re.search(r"^[a-z]+\Z", s, re.MULTILINE)` | 匹配（`\Z` 恒串尾） |
| `re.fullmatch(r"[a-z]+", s)`               | 不匹配              |

要"无论什么标志都严格整串"，用 `re.fullmatch` 或 `\Z`。Pydantic 的 pattern 默认没有 multiline，除非模式里显式写 `(?m)`。

## 常用元字符

| 片段                | 含义                               |
| ------------------- | ---------------------------------- |
| `^` `$`             | 串首 / 串尾锚点                    |
| `.`                 | 任意字符（默认不含换行）           |
| `*` `+` `?`         | 0 次以上 / 1 次以上 / 0 或 1 次    |
| `{m,n}`             | m 到 n 次；`{2,}` 表示至少两次     |
| `[abc]` / `[^abc]`  | 字符集合 / 取反                    |
| `[a-z0-9_-]`        | 范围与字面量；`-` 放末尾或写 `\-`  |
| `\d` `\w` `\s`      | 数字 / 单词字符 / 空白，大写为取反 |
| `(...)` / `(?:...)` | 捕获组 / 非捕获组                  |
| `\|`                | 或                                 |

字符组里有三个位置有讲究：`-` 放开头或结尾才是字面量，`^` 放开头表示取反，`]` 放开头是字面量。

## `\w` 和 `\d` 是 Unicode 感知的

实测 `^\w+$`：

| 输入        | 结果     |
| ----------- | -------- |
| `"abc123"`  | 通过     |
| `"中文"`    | **通过** |
| `"中文abc"` | **通过** |
| `"a-b"`     | 拒绝     |

`^\d+$` 连全角数字 `"１２３"` 也通过。所以要"只允许 ASCII"就不能用 `\w`，得显式写 `[a-zA-Z0-9_]`——用户名这类规则尤其要注意。

## Pydantic 不支持环视与反向引用

```python
Field(pattern=r"(?=abc)")   # 环视
Field(pattern=r"(a)\1")     # 反向引用
```

两种写法在 Python 标准库 `re` 里都合法，但 Pydantic v2 的 pattern 交给 Rust regex 引擎执行，遇到会在**类定义时**直接抛 `SchemaError: Error building ... str validator`，而不是等到校验时才报错。需要"至少包含大小写字母和数字"这类规则时，改用 `field_validator` 自己判断。

## 长度与正则分开写

```python
Field(min_length=3, max_length=30, pattern=r"^[a-zA-Z0-9][a-zA-Z0-9_-]*$")
```

长度按**字符**计（`"中文"` 算 2 个字符，不是 6 字节），正则只管字符集与结构。分开写的另一个好处是 422 返回的 `type` 能区分场景——`string_too_short`、`string_too_long`、`string_pattern_mismatch`——前端可以据此给不同提示。

## 可以直接抄的模式

| 用途                            | 模式                          |
| ------------------------------- | ----------------------------- |
| 用户名（ASCII，不以分隔符开头） | `^[a-zA-Z0-9][a-zA-Z0-9_-]*$` |
| slug（小写字母数字与连字符）    | `^[a-z0-9]+(?:-[a-z0-9]+)*$`  |
| 话题标签                        | `^[a-z0-9-]+$`                |
| 手机号（11 位、1 开头）         | `^1[3-9]\d{9}$`               |

密码强度这类需要环视的规则（如"至少各一个大小写字母和数字"）在 Pydantic 里得用 `field_validator` 实现。
